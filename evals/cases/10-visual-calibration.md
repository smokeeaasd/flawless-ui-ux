# 10: Visual calibration

These four manual runs evaluate presence, competing emphasis, ambiguous refinement, and the separation of visual and editorial scope. They are supplemental to the core matrix and have not been performed.

## Prepare independent copies

Use fresh copies of the indicated fixtures and independent sessions. Runs A and D start from the same unchanged [brand-page](../fixtures/brand-page/); runs B and C start from the same unchanged [dashboard](../fixtures/dashboard/). Never chain one run's changes into another. Use the [host setup and isolation instructions](../README.md) and explicit invocation prefix; submit only the selected task block.

Record the fixture snapshot, skill revision, host, model, settings, available tools, and any initial rendered evidence. When comparing skill revisions, hold the starting files and conditions constant. Preserve first completed results before coaching, and keep evaluator criteria outside agent workspaces.

## A: Strengthen presence

```text
Refine the Radiant After Hours page so visitors can find the ticket-interest action more readily while reading the event details. Improve the action's visual presence and relationship to the surrounding content. Keep the existing wording, event facts, destinations, and local form behavior. Use the current HTML, CSS, JavaScript, system fonts, and local resources. Verify with available tools and summarize the adjustment and checks.
```

Evaluate the concrete relationship changed, not just whether the button became larger. The gradient, rounded uppercase headline, pill actions, and overall expressive character should remain recognizable where compatible with the task and access. Inspect the action alongside the date, location, and price at corresponding wide and narrow sizes. Keep all visible wording, form fields, validation, and honest local-demo feedback. Focus and contrast can be corrected within the intervention.

## B: Redistribute competing emphasis

```text
Refine the Benchroom dashboard's hierarchy so a receptionist can find a bicycle, understand its repair status, and use its pickup action. The overview and working queue need clearer relative emphasis. Preserve every record, field, total, wording, search/filter behavior, and ready-for-pickup interaction. Use the current stack, system fonts, and local resources. Verify with available tools and summarize the adjustment and checks.
```

Evaluate whether the queue and record actions support the task while useful summary information and density remain. Smaller summaries, quieter colors, or fewer containers are not success by themselves. Preserve all six records, initial whole-queue counts, identifiers, customers, bicycles, due dates, estimates, and statuses. Filters must preserve whole-queue summary meaning; marking a filtered job ready must update membership, counts, and feedback correctly. Inspect the retained indigo identity, legible information, and affected keyboard and narrow-screen paths where tools permit.

## C: Interpret an ambiguous refinement

```text
Refine the existing Benchroom dashboard to feel more professional for daily workshop operations. Keep the product facts, wording, data, and functionality. Use the current stack, system fonts, and local resources. Verify with available tools and summarize the changes and checks.
```

Evaluate how the agent translates the request into an actionable goal using the existing interface. A neutral palette, lighter type, or generic enterprise styling is not an implied requirement. Identify a specific improvement in hierarchy, consistency, finish, or task clarity and compare the character retained. Routine decisions can proceed; a genuine identity or scope ambiguity can justify a focused question. No new visual world, business claim, service, dependency, or integration should be invented to satisfy the adjective.

## D: Editorial scope control

```text
Refine the Radiant After Hours page's wording so visitors understand the event and what the ticket-interest form actually does. Improve clarity and remove repeated promotional wording if present. Change wording only, preserving the visual design, existing facts, destinations, validation, and local-demo behavior. Use the current local project and verify with available tools. Summarize the edits and checks.
```

Runs A and D provide the complementary scope controls. In A, wording remains fixed while visual changes address the requested relationship. In D, the palette, type system, imagery, styles, structure, and behavior remain fixed while wording can improve. Compare each final result with the original fixture, not with the other run's output. If there is no redundant phrase, do not require a deletion. Necessary instructions, the event name, date, time, location, £18 price, and local-demo limitations must remain accurate. A text edit that creates a layout concern outside scope should report it rather than silently restyling the page.

## Evidence and acceptance

Use the shared [rubric](../rubric.md) and [report template](../report-template.md). For each run, record:

- The diagnosed difference, intended improvement, intervention, and concrete effect, when observable. Reading the calibration reference is not a pass condition by itself; clear local corrections can use craft guidance directly.
- Baseline and final hierarchy, proportions, visual character, content, and relevant states under matched conditions. A stylistic change alone does not prove improvement, and missing rendered evidence remains unobserved.
- Preserved facts, functionality, and scope. Inspect the complete diff and untracked files; source changes and actual interaction results are separate evidence.
- Completed checks, unresolved limitations, and any assistance. Use met, failed, or unobserved with reasons; do not assign an automatic aesthetic score.

The cases test the guidance, not a required palette, font family, number of effects, or amount of minimalism. Package checks and prepared prompts do not establish successful host behavior.
