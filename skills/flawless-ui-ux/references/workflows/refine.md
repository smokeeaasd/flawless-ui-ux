# Refine

Use for an improvement to an existing screen, component, interaction, or visual aspect. This is the default when an existing interface should improve without an explicit replacement direction. Preserve the incumbent identity and everything outside the requested intervention.

## Bound and diagnose the problem

Inspect the named target and enough surrounding implementation and content to identify the cause. Recover the visitor's task and protected decisions from existing context. A missing design document does not authorize replacing the system visible in components and styles.

Translate a vague symptom into something actionable: equally emphasized text can obscure priority; a distant error can make recovery difficult; a filter can leave a misleading whole-page total. Distinguish evidence from hypotheses. Use [Review](../review.md) when a diagnosis needs further inspection.

Choose only guidance that changes this intervention. Typography may need the relevant [Craft](../craft.md#typography) section and focused verification. A filter or submission change may need the relevant task and [Interaction](../interaction.md) sections. Do not load an entire dashboard or journey procedure for a heading adjustment.

If generic-looking output is part of the concern, use only the affected [prevention sections](../anti-slop.md). Establish a consequence within the target and preserve intentional treatments. The presence of another familiar pattern elsewhere does not widen this request.

## Choose a proportional intervention

Identify the lever that addresses the cause: hierarchy, grouping, wording, state feedback, control behavior, or another relevant change. Decide how improvement will be checked and what could regress.

Use [Visual calibration](../calibration.md) for a broad visual request or unresolved problem in presence, hierarchy, expression, or finish. It connects the existing intention to a diagnosis, proportional intervention, and comparison. Clear local adjustments can use the relevant Craft section directly; copy-only and behavior-only work do not need calibration.

Preserve colors, content, component structure, or behavior when the request fixes them. Text wrapping caused by an authorized type change can be necessary; changing the palette to solve the same problem is a separate decision. Compare alternatives only if their effects matter to the task.

Inspect the reach of shared styles and components before editing. A global heading rule can affect routes beyond the target; a token change can reach unrelated controls. Prefer a change whose reach matches the request. If a material expansion is needed, explain the dependency and continue work that remains authorized rather than silently widening the assignment.

Planning-only requests end with the diagnosed cause, proposed intervention, protected decisions, and checks.

## Implement and verify the target

Reuse established tokens and accessible interaction primitives. Make necessary coupled changes inside the boundary, preserving unrelated content and product behavior. Do not create a new visual direction or project documentation as part of an ordinary focused adjustment.

Check the improved aspect and its dependent states. Use real labels, values, and relevant content extremes. For changes to shared rules, inspect affected neighboring uses; for a local change, keep verification focused. Include the widths and input methods that can reveal regressions in this intervention.

For calibrated work, compare the intended improvement and preserved character using the same content, states, and widths where evidence permits. A change in visual register alone does not establish success. Use [calibration comparison](../calibration.md#compare-the-result) for this check rather than restarting direction selection.

When copy editing is authorized, use the [editorial pass](../tasks/content-interfaces.md#editorial-pass). If the request preserves wording or only concerns visual changes, retain it and report a material repetition problem separately. Copy cleanup and visual simplification are independent decisions.

Correct observed failures and repeat the affected checks after the last edit. Untouched defects outside scope do not become an obligation to redesign the rest of the product. If unavailable tools leave an aspect unverified, say so using the evidence distinctions in [Review](../review.md#establish-the-evidence).

**Completion:** the requested problem is addressed, protected decisions remain intact, and the change set is proportional. Explain the material adjustment and actual verification without turning a small change into a full audit report.

## Examples

**Typography only:** if the page title and summary values look equivalent, establish clearer text roles through permitted size, weight, and line-height changes. Check wrapping against the actual layout and labels. Keep the palette and outer spacing fixed when requested, and confirm protected files remain unchanged. Source inspection can explain intended hierarchy; rendered readability still needs rendered evidence.

**Form feedback:** if a submission error is detached from its field, use the relevant [form guidance](../tasks/forms-and-journeys.md#feedback-and-recovery). Associate the message, preserve the entered values, and provide a sensible focus path. Retain the hero and brand treatment. Check a valid and invalid path where possible; do not replace the whole page to improve one interaction.

**Copy only:** if several sections promise the same benefit, replace redundant lines with distinct confirmed information or remove them. Recheck wrapping, but keep the palette, type system, imagery, and controls. Report any layout adjustment required by the new wording if it exceeds the request.
