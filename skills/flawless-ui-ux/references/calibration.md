# Visual calibration

Use when a broad refinement request ("make it look cleaner", "more polished", "more enterprise", "more impactful") leaves the exact intervention open. Focused local fixes can proceed directly with the owning craft reference.

## Preserve and elevate, never flatten

Refinement must **never** strip away an interface's visual personality, warm/dark surface character, scale contrast, or color identity in the name of "cleaning up." Turning an expressive layout into anonymous monochrome cards is a regression, not polish.

Translate vague requests into specific visual upgrades while keeping authorized character and protected wording intact:

| Request / symptom | Root visual diagnosis | Proportional craft upgrade |
|---|---|---|
| "Looks generic / template-like" | Equal card boxes, timid type scale, dead gray borders | Break symmetry (`7fr 5fr`), widen display-to-body ratio, add one signature visual anchor |
| "Feels cluttered / noisy" | Weak grouping ratios, competing accents, thick borders | Tighten internal spacing vs. outer gaps, replace heavy strokes with `1px` hairlines, focus accent to `<= 10%` |
| "Looks flat / unfinished" | Single surface luminance, raw `#fff`/`#000`, default tracking | Introduce hue-tinted OKLCH surface steps, optical display tracking, concentric radii, tactile hover/focus states |
| "Hard to scan / buried action" | Tall fluff header or uniform KPI tiles pushing work down | Reorder around primary task, compact secondary totals, align amounts with `tabular-nums` |

## Diagnose before changing the vocabulary

Capture the current interface with real content first. Write a brief working diagnosis:

- **Observation & consequence:** e.g., *At 1440px, four saturated KPI tiles draw equal attention and push the repair queue below the fold; at 390px, the 6-column grid overflows horizontally.*
- **Cause & intervention:** compact summary figures into a crisp aligned strip, let the record queue lead, and stack secondary fields under the identifier on mobile while keeping status and primary action visible.
- **Protected choices:** preserve existing brand hues, copy, and working interactions.

Keep visual-only edits within visual scope (report copy issues separately without rewriting protected text); keep copy-only edits within copy scope.

## Compare and verify before/after

Compare before and after captures at **matching viewport, content, scroll position, and state** (`390px` and `1440px`):

1. Did the primary task become faster to orient and act on?
2. Did visual craft—type hierarchy, surface separation, spacing rhythm, and finish—visibly improve without flattening product identity?
3. Are all protected facts, records, calculations, and interactions still intact?
