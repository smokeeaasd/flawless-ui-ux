# Visual calibration

Use this reference within refinement when a broad visual request or an unresolved problem in presence, hierarchy, expression, or finish needs diagnosis. A clear local correction can go directly to the relevant [Craft](craft.md) section. Calibration develops the existing intention; replacement of the visual identity belongs to [Redesign](workflows/redesign.md).

## Identify the intention

Inspect the target, its real content and states, the surrounding system, and current rendered evidence when available. Recover the audience, intended experience, useful action, and recognizable identity from the request and implementation. Name the decisions that must remain: wording, facts, behavior, imagery, typography, palette, or composition as applicable. Missing documentation does not erase an identity visible in the product.

Translate "more professional", "enterprise", "more impactful", or "more polished" into a concrete goal for this surface. A frequent operator may need clearer exception handling; a public event page may need a more compelling invitation and a findable action. Those goals do not settle saturation, font weight, visual density, or image style by themselves.

Ask when an unresolved choice would change identity or scope. Otherwise make routine visual decisions from the available context and continue. Keep only a short working intention and proposed check in the conversation or existing project record; this is not a required report or approval stage.

## Diagnose the difference

Locate the region and state where the current result diverges from the goal. Separate observations from source-based expectations. A different color value is not evidence of improvement; describe what competes, disappears, fails to align, or interrupts the intended rhythm.

| Need | Inspect | Possible intervention |
|---|---|---|
| Important content or action has too little presence | Placement, relative scale, contrast, adjacent emphasis, relevant imagery, and information relationships | Strengthen the useful focal point or give it a better relationship to supporting content |
| Several elements compete for attention | Reading order, grouping, proportions, repeated emphasis, spacing, and workload | Redistribute emphasis and rhythm while retaining useful content and identity |
| The interface feels inconsistent or unfinished | Type roles, wrapping, alignment, image crops, component treatments, states, and transitions | Resolve the specific relationships or missing states instead of replacing the whole system |

These needs can overlap. Choose what explains the problem rather than completing every row. Neither reducing nor increasing visual expression is an automatic correction. Identity and atmosphere can be legitimate reasons for a treatment, alongside task clarity and functional meaning.

## Choose and implement the intervention

Select the relevant lever or coupled changes: typography, composition, spacing, color, imagery, details, or motion. Explain the expected consequence briefly enough to check it later. Reuse the existing system where it serves the goal. Inspect shared styles before changing them so the reach of the edit matches the request.

Use the needed [Craft](craft.md) sections for execution and [Interaction](interaction.md) for controls, access, states, or motion. An existing image can gain presence through a better crop or scale; a palette can remain expressive while its emphasis becomes clearer. Additional assets or effects are choices governed by the task and available resources, not proof of calibration.

Different contexts can justify different responses to the same symptom:

| Symptom and context | Intervention and reason | What to check |
|---|---|---|
| A ticket action is lost in an expressive event page | Give it a clearer position and separation from adjacent details, retaining the gradient and typographic character | The action is findable with the event details at wide and narrow sizes; keyboard focus remains visible |
| A record action is hard to find in a dense workspace | Align it consistently with its record and status rather than turning every row into a large call to action | Users can locate and operate the relevant action in full and filtered views without losing record context |
| Images and metadata compete in a visual collection | Adjust image scale and metadata grouping while preserving the chosen palette and work | The artifacts lead, but titles and navigation remain legible and operable |
| Summaries compete with the working queue | Change their proportions and emphasis relative to the records while keeping meaningful totals and density | The queue leads the intended task; totals, units, filters, and actions retain their meaning |
| A reading page looks unfinished | Resolve actual title wrapping, paragraph measure, figure alignment, or caption spacing within the current type system | Reading and wayfinding become coherent across affected widths and enlarged text |

Do not apply these examples as presets. A larger button, neutral surface, new font, or quieter image may be appropriate in one case and weaken another. Correct the diagnosed relationship.

Keep copy editing separate. Use the [editorial pass](tasks/content-interfaces.md#editorial-pass) when wording changes are authorized. In a visual-only request, preserve protected text and report material repetition separately. Changing slogans is not a reason to restyle the interface, and retaining protected wording is not failure of visual calibration.

## Compare the result

Use the evidence distinctions in [Review](review.md#establish-the-evidence). Compare the same content, state, and viewport where baseline evidence exists. Check both the intended improvement and the recognizable character retained: hierarchy, proportions, rhythm, type and color roles, imagery, and detail. Recheck affected controls and accessible behavior independently of visual appearance.

Correct material gaps within scope and repeat the affected observations after edits. Stop when the diagnosed issue is resolved and relevant checks support the result, or identify the specific limitation preventing verification. Do not continue tuning unrelated dimensions to justify the procedure. With no rendered inspection, distinguish completed source work from unverified visual expectations.

Deliver the material adjustment, its observed consequence, preserved decisions, and any remaining limitations. A screenshot, source diff, or passing build alone does not establish the whole result.
